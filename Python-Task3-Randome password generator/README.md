# KeyShield — Cryptographically Secure Password Generator

A production-ready desktop application built with Python, `tkinter`, and the cryptographically secure `secrets` module. Designed with modern cybersecurity best practices, **KeyShield** generates high-entropy, mathematically unbiased passwords resilient against modern brute-force and dictionary attacks.

## Core Features

- **Cryptographically Secure PRNG (CSPRNG):** Exclusively uses Python's built-in `secrets` module backed by kernel entropy (`CryptGenRandom` / `BCryptGenRandom` on Windows, `getrandom` on Linux, `urandom` on macOS).
- **Strict Inclusion Guarantee:** Mathematically guarantees that at least one character from *every* selected character class is included in the output password.
- **Cryptographic Fisher-Yates Permutation:** Shuffles the generated password using an unbiased Fisher-Yates algorithm powered by `secrets.randbelow()`. Never uses `random.shuffle()`.
- **Strict Validation Rules:**
  - Enforces a minimum password length of 8 characters (with a GUI warning dialog preventing weak configurations).
  - Enforces a minimum of 2 character categories to ensure keyspace diversity.
- **Dynamic Password Strength Meter:** Calculates Shannon entropy in real-time ($H = L \cdot \log_2(R)$) and provides visual and categorical ratings (*Weak*, *Medium*, *Strong*, *Very Strong*).
- **Ambiguous Character Filter:** Toggles complete exclusion of easily misread characters (`0`, `O`, `1`, `l`, `I`, `|`).
- **Seamless Clipboard Integration:** Integrates `pyperclip` with automatic clipboard copying upon generation, plus manual copy buttons with animated status feedback.
- **Ephemeral Session History:** Displays the last 5 generated passwords directly in the GUI. For privacy, history exists **strictly in volatile RAM** and is never persisted to disk or databases.
- **Shoulder-Surfing Protection:** Includes an in-GUI password masking toggle (`••••••••`) for secure use in public environments.

## Security Architecture: `secrets` vs `random`

> [!CAUTION]
> **Never use Python's `random` module for generating passwords, encryption keys, tokens, or security credentials.**

### The Flaw with Python's Standard `random` Module
Python's standard `random` module implements the **Mersenne Twister algorithm (MT19937)**:
- **Deterministic and Predictable:** The Mersenne Twister is a pseudo-random number generator (PRNG) designed for statistical simulations and numerical modeling, **not** cryptography.
- **State Recovery Attack:** The internal state of MT19937 consists of only 624 32-bit words (approximately 2.5 KB). If an adversary observes 624 consecutive outputs (or fewer with algorithmic optimizations), they can reconstruct the entire internal state and predict every future and past "random" value generated by that instance.
- **Predictable Seeding:** `random.seed()` typically relies on system timestamps or process IDs, which attackers can easily narrow down and brute-force.

### Why `secrets` is Cryptographically Secure
The `secrets` module (introduced in Python 3.6 under [PEP 506](https://peps.python.org/pep-0506/)) is specifically designed for secrets management and cryptography:
1. **OS Kernel Entropy:** `secrets` accesses the operating system's Cryptographically Secure Pseudo-Random Number Generator (CSPRNG):
   - **Windows:** `BCryptGenRandom` / CryptoAPI
   - **Linux:** `getrandom(2)` syscall (reading from kernel entropy pools)
   - **macOS / BSD:** `getentropy(2)` / `/dev/urandom`
2. **Cryptographic Indistinguishability:** Outputs from `secrets` satisfy the *next-bit test*: given the first $k$ bits of an output sequence, there is no polynomial-time algorithm that can predict the $(k+1)$-th bit with probability greater than $0.5 + \epsilon$.
3. **Hardware Entropy Sources:** Modern OS CSPRNGs harvest non-deterministic entropy from physical interrupts, hardware events (thermal noise, disk controller timings, network frame intervals), and CPU instructions like `RDRAND`/`RDSEED`.

## Application Architecture & Code Organization

The application is structured following clean **Object-Oriented Programming (OOP)** principles within [`main.py`](file:///f:/OASIS/Random_Password_Generator/main.py):

```
Random_Password_Generator/
├── main.py              # Complete application code (OOP structure)
│   ├── PasswordCriteria         # Dataclass for user configuration
│   ├── PasswordGenerator        # Core cryptographic engine (secrets)
│   ├── PasswordStrengthAnalyzer # Shannon entropy & strength calculator
│   ├── SessionHistoryManager    # Volatile FIFO in-memory buffer
│   └── PasswordGeneratorApp     # Tkinter UI application controller
├── requirements.txt     # Production dependencies (pyperclip)
└── README.md            # Comprehensive documentation & security guide
```

### Architectural Highlights
1. **Separation of Concerns:** The core cryptography (`PasswordGenerator`) and analytical evaluation (`PasswordStrengthAnalyzer`) are decoupled from the Tkinter GUI (`PasswordGeneratorApp`), allowing standalone testing or scripting.
2. **Fisher-Yates Cryptographic Shuffle:**
   ```python
   # Cryptographic permutation ensuring uniform distribution
   for i in range(len(password_chars) - 1, 0, -1):
       j = secrets.randbelow(i + 1)
       password_chars[i], password_chars[j] = password_chars[j], password_chars[i]
   ```
3. **Shannon Entropy Formula:**
   $$\text{Entropy (bits)} = L \cdot \log_2(R)$$
   where $L$ is the password length and $R$ is the size of the combined pool of enabled characters.

## Threat Model & Security Safeguards

| Threat Vector | Mitigation in KeyShield |
| :--- | :--- |
| **PRNG Seed Recovery / State Reconstruction** | Exclusively uses OS kernel entropy via `secrets` (CSPRNG). No internal states can be calculated by an attacker. |
| **Weak / Short Password Attacks** | Strict hard-coded check enforcing a minimum length of 8 characters and at least 2 character categories. |
| **Accidental Category Omission** | Strict inclusion guarantee ensures that even short lengths retain full character diversity. |
| **Shoulder-Surfing (Visual Snooping)** | UI includes a password masking toggle (`••••••••`) for session history items. |
| **Data Remanence on Disk** | Session history exists only in volatile memory (`collections.deque` in RAM). Zero files, caches, or databases are created. |
| **Clipboard Locking / Faults** | Built-in fallback handles OS clipboard locking gracefully without crashing the UI. |
